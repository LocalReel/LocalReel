# LocalReel 0.5.7

The release that gives the product two shapes, a desktop window, and a way to
hand a single film to someone who has no account here.

## Changes

### Two editions

Windows now ships the product twice from one build:

| Download | Size | What it installs |
| --- | --- | --- |
| `localreel-<version>-x64-desktop-setup.exe` | ~150 MB | server + the Electron window |
| `localreel-<version>-x64-desktop.msi` | ~124 MB | the same, as an MSI |
| `localreel-<version>-x64-setup.exe` | ~7 MB | server only |
| `localreel-<version>-x64.msi` | ~6 MB | server only, as an MSI |
| `localreel-<version>-x64.zip` | ~6 MB | server only, portable |

The two are separate products to Windows (own upgrade codes, own entry in Apps &
Features) that declare each other, so installing one replaces the other rather
than leaving two entries pointing at one folder.

In-app updates follow the edition that is installed. `localreel-update` reads the
install directory, picks `setup-desktop` when `desktop/LocalReel.exe` is there and
`setup` when it is not, and never turns a 6 MB server install into a 150 MB one
behind the user's back.

### A desktop window

- `desktop/` is an Electron shell that loads `http://127.0.0.1:<port>` — never
  `file://` — so the UI keeps its cookie session, its relative API paths and its
  CSP.
- It attaches to a server that is already running and only stops one it started
  itself.
- Before an install replaces files on disk the window has to be gone: when the
  server exits (a crash or an update), the window closes; `before-quit` waits for
  the child process before the app exits.
- There is no `electron-updater`; the signed `update.json` remains the only path.
- The shell is packaged into the installer by `scripts/harvest-desktop.ps1`, and
  also builds a `.dmg` and an `.AppImage` on macOS/Linux.

### Share links

- One item, one random token (122 bits), a page at `/s/<token>` that renders
  **outside** the sign-in gate and talks to one endpoint.
- Links expire, can be revoked, and can allow or refuse downloads — refusal is a
  separate endpoint answering 403, not a hidden button.
- Share requests have their own budget (120/minute per token) and never touch the
  transcoder.

### Phones on the same network

- Off by default. The console leads with a card that says what the situation is,
  what the address would be, and offers the one switch that changes it.
- Turning it on writes `[server] allow_remote` into the configuration file and
  says a restart is needed; nothing rebinds a listener under someone watching a
  film.
- The request guard was rewritten: with remote access on, a browser that sends an
  `Origin` must name the same authority, or one listed in the new
  `[server] allowed_origins` (for a reverse proxy). Previously enabling remote
  access disabled the guard entirely.

### Console

- **Sessions**: every signed-in browser, with its user agent and last activity,
  and a button that ends it. The id shown is a hash of the token, so an
  administrator can end a session without being handed the ability to use it.
- **Audit**: an append-only record of the actions that are hard to undo — deleting
  a source, stopping the server, creating/changing/deleting an account, changing
  remote access, installing or removing a plugin, restoring a backup. Handlers
  record their own detail; a middleware records any admin mutation that did not,
  so a new endpoint cannot change the machine silently.
- **Server settings**: the configuration the process is actually running with,
  and the remote-access switch.
- Danger zone: shutting the server down moved out of the overview.

### Plugins

- Plugins are a top-level module (`/plugins`, `/plugins/:id`) with their own rail
  entry; the old `/admin/plugins` URLs redirect.
- A package may declare `icon` in its manifest (svg/png/webp, package-relative,
  no `..`); the host reads it out of the signed package and serves it, and the UI
  falls back to a monogram when there is none.

## Release engineering

- `components.json` now pins a **commit** per component, and a tag build fails if
  they are missing. `scripts/pin-components.ps1` writes them.
- A nightly `smoke.yml` builds the components' `main` and asserts the package, so
  drift is noticed within a day rather than at the next tag.
- The Windows MSI shrank from 141.7 MB to 124.2 MB by shipping only the two
  locales the UI uses.
- The packaged executable now carries the product icon and version resource
  instead of Electron's (`signExecutable: false` keeps rcedit, skips signing).
- Still unsigned: no code-signing certificate, so SmartScreen warns. Verify
  `SHA256SUMS.txt`; the update manifest is signed separately.

## Upgrading

Installers replace the previous version in place and keep `data\`, the library
and `localreel.toml`. A server installation stays a server installation; a
desktop installation keeps its window.
