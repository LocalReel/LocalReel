# LocalReel 0.5.3

The release that puts the library next to the installation, keeps it there when
the program is removed, and stops a double-clicked server from leaving a console
window behind.

## Changes

### The library follows the installation

- A relative `[data] dir` (the shipped example's `"data"`) is resolved against
  **the program's directory**, not the working directory and not the config
  file's folder. Installing into `D:\Apps\LocalReel` keeps the media in
  `D:\Apps\LocalReel\data`; copying that folder to another drive takes the
  library along.
- The same install can no longer end up with a second, empty library because it
  was started from a different folder. The report behind this: the program was
  on `D:\AppData\LocalReel` and the store appeared in `G:\Downloads\data`
  because the server happened to be launched from there.
- `LOCALREEL_*` variables keep command-line semantics: a relative value is
  resolved once against the working directory and then stays absolute.
- The resolved data directory is logged at startup and shown in the banner, so
  the effective location is never guessed from the configured spelling.
- A machine-wide install under `C:\Program Files` cannot write next to itself;
  use an absolute `[data] dir` there, as `docs/install.md` now says.

### Uninstalling no longer takes the library

- The setup executable records the files it wrote in `install.json`; uninstall
  removes exactly those files and prunes the directories they leave empty. A
  library under `<install>\data`, a `localreel.toml` or plugin data stays.
- With no usable manifest the uninstaller keeps `data` and removes the rest.
- The zip uninstaller moves `<install>\data` aside while it removes the program
  and puts it back afterwards.
- `-RemoveData` removes both the folder inside the install and
  `%LOCALAPPDATA%\LocalReel`.

### A double-clicked server hands the console to the tray

- `localreel.exe` started without `--tray` (the double-click case) now installs
  the notification-area icon and hides the console when the console belongs to
  it alone. A terminal launch keeps its console, because the shell shares it.
  The shortcut path was already console-free through `localreel-desktop.exe`.

## Upgrading

- From 0.5.2: install over it, no configuration change needed.
- If your config has a relative `[data] dir` and the library currently lives
  somewhere else (the `G:\Downloads\data` case), move that folder next to the
  installed program before the first launch, or set an absolute path.

## Verification

- Rust: `cargo fmt --check`, `cargo clippy --workspace --all-targets --
  -D warnings`, `cargo test --workspace` - 280 tests.
- Installer: 8 unit tests in the setup crate, plus an install/uninstall cycle
  with a library inside the install folder for both `setup.exe` and the zip
  uninstaller.
- Path rule: the executable copied to a temporary folder with
  `dir = "data"` creates the database next to itself, never in the working
  directory.
