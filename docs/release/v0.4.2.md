# LocalReel 0.4.2

The first release with accounts, and with an installer for every platform the
project targets.

## Changes

### Accounts (ADR-013)

- The first start asks for the owner account. The owner creates one viewer
  account per person; everyone gets their own progress, likes and favourites.
- Passwords are Argon2id hashes; sessions live in the database and are opaque;
  every state-changing request needs the CSRF header.
- The admin page manages accounts: disable, reset a password, delete.
- Backups are household-wide (format v3): they name every account but never
  their password hashes. A version 2 backup still imports into the owner.

### Desktop

- A GUI-subsystem launcher (`localreel-desktop.exe`) starts the server without
  showing a console window. The shortcuts, the wizard's launch entry and the
  session entry all use it.
- Windows gets a notification-area icon: open the UI, quit, and a quiet start
  at login (`localreel autostart enable`).
- macOS ships an ad-hoc signed `.app` in a `.dmg`, with a LaunchAgent template
  for starting at login.
- Linux ships a `.deb` (hardened systemd system and user units, desktop entry,
  icon), an AppImage, and a tarball.
- Where there is no tray icon, **Admin → Server → Shut down server** stops the
  process through the same graceful path as Ctrl+C.

### Server

- The container image runs as a dedicated account, states its persona
  (`LOCALREEL_MODE=server`) and keeps its log in `/data`.
- An experimental Synology `.spk` (DSM 7) starts and stops the server through
  Package Center; it has not been installed on a real NAS yet.
- `docs/reverse-proxy.md` covers Caddy and nginx, including the buffering and
  upload-size rules the SSE stream and backup restores need.

## Verification

- Rust workspace: 174 tests, `clippy -D warnings`, `fmt` — on Windows, Ubuntu
  and macOS runners.
- Web: 25 unit tests, strict TypeScript build, and the browser resume smoke test
  (accounts-aware mock server) on Ubuntu.
- Windows: MSI install, both shortcuts resolve to the launcher, a tray launch
  shows no console window and quits with exit code 0.
- Linux (Ubuntu 24.04): tarball, `.deb` and AppImage build; the extracted
  binaries report `web: embedded`; `systemd-analyze verify` and
  `desktop-file-validate` accept the unit and the entry.
- macOS (GitHub runner): the bundle runs, `doctor` reports the embedded UI, the
  ad-hoc signature is present, the dmg image is valid, and the server answers
  `/api/v1/health` with `setup_required` on a live port.
- Docker: the image builds, starts, answers health, reports `setup_required`,
  and rejects anonymous media requests with 401; the release pushes the same
  image for amd64 and arm64.
- Synology: the `.spk` structure is checked in CI (INFO fields, `package.tgz`
  payload, start-stop script, privilege file).
