# LocalReel 0.5.0

The release that turns "installable and shareable" into "usable as the household
media server": subtitles aside, the library now maintains itself, one machine's
CPU is no longer the queue, films with several audio tracks are playable, and a
plugin can no longer read the database just because it was started.

## Changes

### Automatic library updates

- Enabled local sources are watched (OS notifications, debounced for two
  seconds) and rescanned when files appear. A folder copy produces one
  incremental scan, not one per file.
- Unwatchable sources — a plugin source, an SMB/NFS mount that forwards no
  events, an exhausted inotify budget — are skipped and listed in
  `admin/health` as `watchers.skipped`; nothing else is affected.
- `[scan] watch` (default `true`) / `LOCALREEL_WATCH`.

### One transcode budget

- `[media] max_concurrent_transcodes` (default 2) caps how many ffmpeg jobs run
  at once. Waiting jobs stay **queued** and say so, instead of occupying a
  worker, and a long transcode queue no longer starves scans, probes or
  thumbnails.
- Playback sessions are refreshed by playback/stream/HLS requests; a session
  idle for `idle_session_secs` (default 15 min) has its job cancelled.
- On Linux, less than max(200 MB, 5 %) free memory refuses a new encode with
  `503 busy` instead of swapping.

### Hardware acceleration

- `[media] hwaccel = "auto" | "none" | "nvenc" | "qsv" | "vaapi" | "videotoolbox"`.
  The encoder table is read once at startup; `auto` picks the first usable
  encoder on this platform and falls back to the CPU.
- Each encoder keeps its own quality flags. A device-level failure retries once
  on the CPU and says so in the job message; a corrupt file is not retried.
- `doctor` and `admin/health` report the accelerator actually in use.

### Multiple audio tracks

- Every audio stream is stored (`media_tracks`), with its language normalized
  (`chi`/`zho`/`zh-CN` → `zh`).
- `GET /api/v1/media/{id}/tracks` lists them; `POST …/playback?audio=<track>`
  switches. The default track still direct-plays; another track re-muxes or
  transcodes, because a browser cannot switch embedded audio on a playing file.
- The audio choice is part of the transcode cache key, so two languages never
  overwrite each other.
- Both players gained an audio menu.

### Progress-bar previews

- Long videos (≥ 10 min) get a 10×10 sprite sheet sampled across the whole file,
  and `GET /api/v1/media/{id}/preview.vtt` maps time ranges to tiles. Short
  videos produce no sprite.
- Dragging the Reels scrub bar and hovering the player's preview rail show the
  thumbnail under the pointer.
- `[media] preview_sprites`, `preview_min_secs`.

### Plugin permissions that mean something (ADR-014)

- The sidecar starts with a **cleared environment**: `LOCALREEL_DATA_DIR`,
  `LOCALREEL_CONFIG` and `LOCALREEL_LOG_DIR` no longer reach a plugin, which
  previously made the permission list decorative.
- It runs in `<data>/plugins/<id>/` and is told only about its own source roots
  through `LOCALREEL_PLUGIN_ROOTS`.
- `network` is enforced through a host proxy (`POST /api/v1/plugin-proxy`,
  token-authenticated, 30 s / 32 MiB). Without the permission the call is
  refused and audited.
- `plugin_audit` records starts, allowed requests and refusals; the admin page
  lists each plugin's **effective** permissions and recent activity.
- `storage:read` is implied for storage plugins, so packages written before the
  permission keep loading.

### Optional metadata and posters

- `[metadata] provider = "none" | "tmdb"`, `api_key`, `language`. Off by
  default: with `none` the server never fetches anything.
- Titles are derived from the series grouping or the cleaned filename; matches
  below a confidence threshold are discarded rather than guessed.
- Posters land in `data/cache/posters`; the player shows the poster and the
  overview. Refresh at most once a week, plus Admin → Metadata → Match metadata.

### Smaller ffmpeg installs

- `tools/fetch-ffmpeg.ps1 -Profile probe|mini|full`: `probe` installs only
  `ffprobe.exe`, which is all scanning and cataloguing need. `doctor` reports
  `full` / `probe-only` / `missing`, and a probe-only package scans while
  thumbnails, transcoding and HLS stay off.
- `compose.ps1 -FfmpegDir` accepts a directory with only `ffprobe.exe`.

### Error details without leaking the library

- A failed encode now separates the message everyone sees from the diagnostic
  detail (local path, ffmpeg stderr tail). Detail is serialized only for an
  administrator on loopback, or one running with `RUST_LOG=debug`, and the UI
  folds it behind **Details**.

## Not in this release

Subtitles. The original plan's first work item (embedded/external subtitle
tracks, WebVTT conversion, burn-in) was deliberately excluded; `media_tracks`
already carries the `kind` discriminator it will need, so adding it later is a
policy change rather than a migration.

## Upgrade notes

- Three new migration streams are applied automatically: media `0006` (tracks)
  and `0007` (metadata), plus plugin `0001` (audit). All forward-only, as usual.
- `localreel.toml` gains `[scan]`, `[metadata]` and four `[media]` settings; every
  one of them defaults to the previous behaviour except watching, which is on.
- **Plugins:** a sidecar that relied on inheriting `LOCALREEL_DATA_DIR` or other
  host variables will stop seeing them. That is the point of ADR-014; a plugin
  that needs the network should call the host proxy.
- `localreel-plugin/v1` packages stay valid; no manifest changes are required.
