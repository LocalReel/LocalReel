# LocalReel 0.5.6

The release that replaces the web UI, groups the library into shows, and turns
plugins into capability-gated processes.

## Changes

### The web UI is new

- New information architecture: **Home** (continue watching, shows, recently
  added), **Library**, **Show** (`/show/:id`), **Watch** (`/watch/:id`),
  **Reels** (`/reels`) and a console split into nine sections instead of one
  long page.
- **Every page has a URL.** Navigation uses the History API and the server
  answers any unmatched HTML path with the shell, so a refresh keeps the page
  and a link can be shared. `/watch` without an id redirects to `/reels`, which
  is where the vertical feed used to live.
- One design-system token layer: a default dark theme ("screening room"), a
  light theme and three alternative accents, plus density and motion settings.
  The choice is stored per browser in `localStorage["localreel.ui"]` and applied
  through data attributes, so a theme is a token override rather than a second
  stylesheet.
- Typefaces are self-hosted under `src/fonts/` (SIL OFL 1.1: Newsreader,
  IBM Plex Sans, IBM Plex Mono) because the server's CSP allows only
  same-origin fonts. CJK text falls through to an explicit
  `Noto Sans SC / PingFang SC / Microsoft YaHei` stack instead of an
  uncontrolled serif fallback.
- **Plugin management** in the console: a list with lifecycle state and
  restart/enable/disable, and a detail page with requested versus granted
  capabilities (tier, scope, source, audit level), secret handles, the log tail
  and the audit trail. Secret values are stored in the host and never rendered.
- Accessibility: one `:focus-visible` treatment, focus-trapped dialogs that
  return focus, a skip link, keyboard-navigable tabs, and native dialogs
  replaced by an in-app confirmation component. Every colour pair in both
  themes was measured against WCAG AA.
- Bilingual: English and Simplified Chinese dictionaries keep their parity gate
  (key set and placeholder set), with the language resolved from
  `localStorage["localreel.lang"]`, then the browser.
- Still two runtime dependencies (`react`, `react-dom`) plus a lazily imported
  `hls.js`; the router, the query cache and the component primitives are part of
  the application.

### The library is grouped into shows

- `Media` now carries `series_key`, `series_title`, `episode` and `series_id`, a
  stable 16-hex identifier derived from the key, so a link can name a show
  without carrying a filesystem path.
- **`GET /api/v1/series`** returns one entry per show with its episode count,
  how many episodes the calling account has watched, the episode it touched
  most recently, and a poster. **`GET /api/v1/series/:id`** returns the show and
  its episodes in episode order (specials last).
- The UI uses it for the home page and the show page; the library grid still
  lists files, which is what a viewer needs when the scanner could not group
  something.

### Client-side routes survive a refresh

- Any unmatched path that accepts HTML returns `index.html` with
  `Cache-Control: no-cache`. Paths under `/api/` still answer the JSON 404
  envelope, so a typo in an endpoint does not come back as a web page.

### Plugins request capabilities and the host grants them

- Manifests declare capabilities with typed scopes. The console shows requested,
  pending, granted and forbidden capabilities, and a grant is only accepted for
  a capability the manifest actually asked for.
- The **broker** executes `net.fetch`, `fs.read`, `secret.use` and
  `catalog.write` on the plugin's behalf; the host applies the scope. `fs.read`
  is bounded by granted roots and re-verified from the opened handle rather than
  from a path.
- Secrets live in the host and are injected per request. The sidecar no longer
  inherits `LOCALREEL_DATA_DIR` or `LOCALREEL_CONFIG`.
- **Schedules** run through the host, with admin endpoints to list and delete
  them.
- **Package verification**: SHA-256 pinning, publisher signatures, key rotation
  and revocation, with the verification chain surfaced in the descriptor.
- **Isolation**: a Windows AppContainer (and a network namespace on Linux) per
  plugin, per-plugin overrides, stale-profile sweeps at startup and at exit, and
  bounds on memory and the process tree.
- Plugins get their own quota-bound blob namespace; other plugins' namespaces
  are not reachable.

## Upgrading

- Install over 0.5.5. Migrations are forward-only and run on start; libraries,
  accounts and watch progress are unchanged.
- Bookmarks to the old feed (`/watch`) redirect to `/reels`. The player that
  used to open as an overlay in the library is now a page at `/watch/:id`.
- The console moved from one long `/admin` page to nine sections; `/admin` is
  the overview.
- The old browser keys are preserved: `localreel.lang` keeps the language
  choice. The new appearance settings start from the default theme.

## Verification

- Rust: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --
  -D warnings`, `cargo test --workspace` - 391 tests across 27 binaries.
- Web: `tsc --noEmit`, `npm test` (51), `npm run build` - all green, plus the
  headless Chrome resume smoke against the mock API.
- End to end: the release binary serves the new UI from its embedded `dist/`;
  the shell is returned for `/library`, `/show/:id`, `/watch/:id`, `/reels` and
  `/admin/plugins/:id`, and `/api/v1/<unknown>` still returns the JSON 404.
- Responsive checks at 390, 768 and 1440 pixels with a 262-item library.
