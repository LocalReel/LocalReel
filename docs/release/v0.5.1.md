# LocalReel 0.5.1

The release that makes plugins a supervised part of the system instead of a
process started once, and gives Windows a per-user installer that stays
per-user.

## Changes

### Plugins are supervised

- A plugin now has a lifecycle the server owns: `starting`, `running`,
  `unhealthy`, `failed`, `disabled`, `stopped`. The admin page shows the state,
  the reason it is not running and how many times it has restarted, instead of
  a boolean that said `running: false` for both "switched off" and "crashed".
- One supervisor thread owns every transition. Callers only state an intent
  (`restart`, `set_enabled`) and the thread converges observed state towards it,
  so a start superseded by a newer intent cannot race it.
- A process that dies on its own is noticed within 250 ms and restarted with
  1/2/4/8/16 s backoff, five attempts. Permanent failures are not retried: a
  corrupt package, an unreadable manifest or a wrong API version stops the
  plugin and reports why; a handshake timeout still retries.
- `GET /v1/health` runs every 10 s with a 2 s budget. Three consecutive failures
  mark the plugin `unhealthy`; six replace the process; three such restarts
  stop it.
- Stopping drains before it kills: the gate refuses new calls, in-flight
  requests (bounded by `stop_timeout_secs`, default 5 s) finish, the provider is
  removed, stdin is closed, then the process is terminated.
- Children no longer outlive the server. Windows gets a job object with
  `KILL_ON_JOB_CLOSE`, Unix a process group, and the server handles SIGTERM so
  `systemctl stop` / `docker stop` take the same drain path as Ctrl+C.

### Control plane

- `POST /api/v1/plugins/{id}/restart`, `POST .../enable`, `POST .../disable` and
  `GET .../logs` (the tail of the sidecar's stderr).
- `?persist=true` rewrites only the matching entry's `enabled` in
  `localreel.toml`, keeping comments and formatting (`toml_edit`); without it
  the switch lasts until the server restarts.
- State changes publish `plugin_state_changed`.
- The admin page gains Restart / Enable / Disable / Logs, in both languages.

### Observability

- The sidecar's stderr is kept in a 64 KiB ring buffer; the log endpoint serves
  the tail.
- `plugin_audit` is pruned daily, keeping 30 days.
- `doctor` prints the plugin list and the failure policy.

### Windows: a per-user setup that stays per-user

- New download: `localreel-<version>-x64-setup.exe`. It installs for the
  current user only - no administrator prompt, no machine-wide changes.
- It picks its language from Windows (Chinese and English today), and `/lang=`,
  `/S`, `/D=<folder>`, `/uninstall` and `/removedata` cover unattended use.
- The program goes to `%LOCALAPPDATA%\Programs\LocalReel`; the library stays in
  `%LOCALAPPDATA%\LocalReel` and is never written by the installer. Uninstall
  removes the program and keeps the library.
- The MSI remains for machines where several Windows accounts share one
  installation; the documentation now presents it that way. Windows Installer
  promotes a per-user package to a machine-wide registration when an
  administrator runs it, which is recorded in ADR-016.

## Upgrading

- From 0.5.0 MSI: uninstall it once, then run the new setup. Pre-1.0, the
  installer identity changes; previously registered MSI installs are not
  upgraded silently by the setup.
- Configuration files do not change. A plugin entry may now carry
  `enabled = false`; `?persist=true` writes it for you.

## Verification

- Rust: `cargo fmt --check`, `cargo clippy --workspace --all-targets --
  -D warnings`, `cargo test --workspace` - 275 tests, 0 failures.
- Web: `tsc --noEmit`, `npm test` (30), `npm run build`.
- Live checks: killing the demo plugin produced `exited unexpectedly` and a
  restart about 1.16 s later; restart/enable/disable over HTTP moved the
  generation 1 -> 2 -> 3 and the audit log recorded the starts and stops.
- Installer: silent install, reinstall over itself, uninstall keeping the
  library, both languages, desktop shortcut through a redirected Desktop
  folder.
