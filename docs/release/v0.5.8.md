# LocalReel 0.5.8 — draft, not published

This is a release candidate preparation record, not a statement that packages
have been published or that all platform checks have passed.

## Changes prepared

- Preserve custom libraries during ordinary uninstall and upgrades: installation
  ownership is derived from payload files, with conservative handling of legacy
  manifests and unsafe paths.
- Improve desktop server startup fallback and error handling, and enforce exact
  navigation origins.
- Pin Electron 44.9.1 to address the reported high-severity dependency advisory.
- Repair player lifecycle and per-media state, cache/request races and error
  feedback, with additional frontend regression and static checks.
- Strengthen server task ownership, shutdown, derived media invalidation and
  request isolation, as recorded in the workspace audit remediation report.
- Add installer/Desktop safety gates and strict cross-component release-version
  validation; reject stale binaries during Windows product composition.

## Validation status and known limitations

Source unit/static checks have been run during remediation. These are not a
substitute for Windows/Linux/macOS package verification or installer integration.
The local Electron runtime download failed with a terminated TLS connection;
patched runtime execution and desktop packaging have not yet been verified.
Windows Sandbox/VM tooling is not available on the current host. The real setup
install/upgrade/uninstall cycle has therefore not been run, and must not be run
against the host user's registry or shortcuts as a substitute.

The desktop build-tool chain still reports six moderate affected packages from
the minimatch advisory. No unverified major-version override or builder downgrade
has been applied. Existing OS signing policy remains unchanged (not equivalent
to trusted Windows Authenticode or macOS notarization). Update manifests require
the existing Ed25519 signing key and verification against the compiled public key.

Before publication: finish runtime/package and disposable-guest checks; commit
and pin the verified component revisions; run the complete cross-platform release
workflow; verify artifact hashes and update signatures; obtain final approval to
push/tag/publish. See [verification preparation](verification-0.5.8.md).
