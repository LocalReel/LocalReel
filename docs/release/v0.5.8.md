# LocalReel 0.5.8

Published on 2026-11-12 from tag `v0.5.8`. The cross-platform release workflow
(`resolve version` → desktop/installer safety → Windows, Linux, macOS, Synology,
Docker smoke, Docker push, manifest → publish) completed successfully; every job
is green.

## Changes

- Give the per-user Windows setup a real window: folder pickers for the program
  and the library, optional Start Menu/desktop shortcuts, progress bar, DPI
  scaling, product icon, and a "start when finished" checkbox.
- Let the installer choose the library folder and record it, so upgrades keep
  using it and uninstall can offer to delete it.
- Record the installation in `HKCU\Software\LocalReel` (`InstallPath`, `Version`,
  `DataDir`) and read it back to keep upgrades at the same location.
- Uninstall removes only the shortcuts that were actually created, and asks
  whether to keep the library (kept by default).
- Preserve custom libraries during ordinary uninstall and upgrades: installation
  ownership is derived from payload files, with conservative handling of legacy
  manifests and unsafe paths.
- Improve desktop server startup fallback and error handling, and enforce exact
  navigation origins.
- Pin Electron 44.9.1 to address the reported high-severity dependency advisory.
- Repair player lifecycle and per-media state, cache/request races and error
  feedback, with additional frontend regression and static checks.
- Strengthen server task ownership, shutdown, derived media invalidation and
  request isolation, as recorded in the workspace audit remediation report.
- Add installer/Desktop safety gates and strict cross-component release-version
  validation; reject stale binaries during Windows product composition.

## Packages

Windows, Linux, macOS and Synology packages are attached to the release, next to
`SHA256SUMS.txt`, `update.json` and `update.json.sig`.

The Windows desktop package `localreel-0.5.8-x64-desktop-setup.exe`
(157,633,024 bytes, SHA-256
`98428bccdbc56f4036b62b2908afea7d4f4a0e5a59f486216a4f1d70e7b2c949`) is built by
the workflow from the same sources as the other packages; it includes the window
described above.

`update.json` advertises `0.5.8` on the stable channel with `min_version`
`0.5.6`; the manifest is signed with the existing Ed25519 key and verified against
the compiled public key during the release.

## Known limitations

- The desktop build-tool chain still reports six moderate affected packages from
  the minimatch advisory. No unverified major-version override or builder
  downgrade has been applied.
- Existing OS signing policy is unchanged: packages are not Authenticode-signed
  or macOS-notarized, so SmartScreen and Gatekeeper warnings remain.
- The full setup install → upgrade → uninstall cycle has not been re-run on a
  disposable machine for this build; the release validates that the installer
  compiles, its tests pass, and the safety gates succeed.
