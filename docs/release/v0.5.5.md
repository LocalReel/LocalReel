# LocalReel 0.5.5

The release that tells you when there is something newer, gives the MSI its
product icon, and turns the `Config.Msi` permission failure into a one-command
repair.

## Changes

### The admin page tracks the latest release

- New Admin card **Updates**: current version, the latest published release, and
  a **Check for updates** button. When a newer version exists the card links to
  its release page and, when attached, directly to the Windows setup.
- Backed by `GET /api/v1/admin/update` (administrators only). The server asks
  the public GitHub API once per `interval_hours` (default 24) and caches the
  answer; `?refresh=true` bypasses the cache for the button.
- It never downloads or applies anything. Silently replacing a binary would be
  a supply-chain hole, so this is a tracker with links.
- `[update]` in the configuration file: `check` (default `true`), `feed` for a
  mirror, `interval_hours`. Set `check = false` on an offline network; the card
  then says so instead of erroring. A failed check is reported on the card and
  never blocks the page.

### The MSI carries the product icon

- `installer/localreel.ico` is the same mark as the tray and the web app, so the
  MSI in Explorer, its shortcuts and the Apps & Features entry no longer show
  the placeholder triangle.

### Config.Msi failures have a repair tool

- `scripts/fix-config-msi.ps1` (also shipped in the zip) probes
  `<volume>\Config.Msi`, takes ownership, resets the ACL and removes the folder,
  refusing to run while an install is in progress. `-Drive D:` targets one
  volume, no argument covers every fixed volume, `-WhatIf` reports only.
- The install guide explains the `Could not set file security ... Error: 5`
  message, points at the script, and notes that the per-user setup does not use
  `Config.Msi` at all.

## Upgrading

- From 0.5.4: install over it. Existing libraries and the install-folder rule
  are unchanged.
